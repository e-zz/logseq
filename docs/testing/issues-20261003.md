## Windows manual test checklist (manual checklist)

事项：以下每一项都请在**新建的图谱或图谱副本**上执行，勿在正使用的图谱上验证。

1. #8 回收站与搜索隔离
   - 回收一个父块（含子块）后，全局页面/块搜索不应再出现被回收子树。
   - 恢复该父块后，子树回到原父级与原顺序，且不产生重复块。
   - 在 Agent/MCP 单块查询中可查到已回收块（`get-recycled-block`）。
2. #8 范围搜索
   - 将搜索限定到某个页面或某个块时，只返回范围内的结果；页面级与块级语义分别验证。
3. #9 类型化属性
   - 为页面/块写入 cv、orcid、topics、description 等属性，重新打开后值保持。
   - 写入 node/date/asset 引用类属性；对已回收目标写入应被拒绝。
   - 写入错误形状的值应被整体拒绝，且数据库无变化。
4. #4 列表与编号
   - 写入 numbered/bullet 列表类型属性，UI 中列表样式与编号正确且不重复编号。
5. #7 任务状态
   - 在新增块和普通块上写 task status 闭集值；未知闭集值应被拒绝。
6. #6 临时 id 嵌套
   - 一次调用中创建多级父子结构（子先于父、临时父引用），落地后父子关系与顺序正确。
7. #5 缺失 order 渲染
   - 造出直接子块缺失 `:block/order` 的情形，列表仍可渲染，缺失项排在最前且不报错。
8. #12 CLI 图谱打开
   - 修改图谱的 config/.css/.js 后关闭并用 CLI 重新打开，改动应保留，不被默认值覆盖。
   - 缺失的默认文件应被重新创建；Windows classpath 正常解析。

## Isolation notes

- 使用**新图谱或图谱副本**测试。单独分发 ZIP 并不能隔离应用的 appData；请采用受支持的隔离启动方式，或直接在**隔离的 Windows 账户/测试环境**中运行，不要臆造未文档化的启动参数。
- 破坏性/持久化用例（回收、属性写入、CLI 打开）务必在可丢弃的副本图谱上进行。
